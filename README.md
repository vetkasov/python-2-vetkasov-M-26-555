# Примитивная база данных

Арсений Веткасов, группа M-26-555.
[Репозиторий, ветка ver2](https://github.com/vetkasov/python2-vetkasov-M-26-555/tree/ver2).

Консольное приложение на Python: создание и удаление таблиц, типизированные
CRUD-операции, сохранение в JSON, подтверждение удаления, замеры времени
и кэширование запросов. Приложение процедурное, без классов.

## Установка и запуск

Требуется [uv](https://docs.astral.sh/uv/getting-started/installation/).
Из корня проекта:

```bash
uv sync --locked
uv run database
```

Также работают `uv run project`, `uv run python -m primitive_db.main`
и `make run`. Поддерживается Python >=3.12; проверяемая версия — 3.12.
Имя дистрибутива — `project-2-vetkasov-m-26-555`, Python-пакет — `primitive_db`.
Настройка `module-name` сборщика uv связывает эти два имени.

## Управление таблицами

```text
create_table users name:str age:int is_active:bool
list_tables
info users
drop_table users
```

`ID:int` автоматически добавляется первым. Имена состоят только из латинских
букв, цифр и `_`, регистр учитывается. Типы пишутся только строчными:
`int`, `str`, `bool`. Повторные столбцы и неподдерживаемые типы отклоняются.
`ID:int` можно явно указать в схеме один раз; он всё равно будет первым.

Метаданные: `db_meta.json`, словарь «таблица → столбец → тип» с сохранением
порядка. Записи: `data/<имя>.json`, файл появляется при первом сохранении записей.
Отсутствующий файл означает пустую таблицу. При `drop_table` он удаляется.
Чтобы `users` и `Users` имели разные файлы на macOS, заглавные буквы
кодируются как `%XX`: `users.json` и `%55sers.json` соответственно.

## CRUD-операции

```text
create_table users name:str age:int is_active:bool
insert into users values ("Sergei", 28, true)
insert into users values ("Ivanov, Ivan",22,FALSE)
select from users
select from users where age = 28
update users set age = 29 where name = "Sergei"
select from users where ID = 1
delete from users where ID = 1
info users
drop_table users
exit
```

Перед удалением записей и таблицы нужно ответить ровно `y`. Любой другой
ответ отменяет операцию. `help` выводит все десять команд; Ctrl+C и конец
ввода завершают работу, в том числе во время запроса подтверждения.

Разбор соответствует ограниченной грамматике задания:

- Один `insert` — одна таблица и одна группа значений в скобках.
- Значения задаются в порядке схемы, без ID; все пользовательские поля обязательны.
- Строки только в одинарных или двойных кавычках; числа и bool — без кавычек.
- `true`, `True`, `TRUE` и другие варианты регистра принимаются как bool.
- Ключевые слова команд пишутся строчными; имена столбцов регистрозависимы.
- `"28"` не подходит для `int`; bool не считается целым числом.
- Пробелы между элементами допускаются; пробелы и запятые внутри строк сохраняются.
- В строках поддерживаются экранированные кавычки и обратный слеш.
- `where` — одно равенство. `update` изменяет один столбец и требует `where`.
- `delete` требует `where`; `select` без условия возвращает все записи.
- Лишние токены, несколько групп `values` и другие нарушения структуры отклоняются.

ID вычисляется как `max(существующие ID) + 1`, начиная с 1. После удаления
последнего ID он может использоваться повторно. Менять ID через update запрещено.
Данные выводятся через PrettyTable, всегда с первым столбцом ID.

## Декораторы, кэш и файлы

`handle_db_errors` обрабатывает ошибки таблиц, столбцов, валидации и файлов.
`confirm_action` применяется к `drop_table` и `delete`. `log_time` измеряет
`insert` и `select` с помощью `time.monotonic()` в формате X.XXX секунд.
Ошибки и отмена не сопровождаются сообщением об успешном изменении.

`create_cacher()` хранит словарь в замыкании. Ключ формируется в engine.py
из имени таблицы и стабильного JSON-представления условия, включая отсутствие
условия. Повторный select использует сохранённый результат. После успешного
сохранения insert/update/delete/drop_table кэшер заменяется новым.
Ошибки и отменённые изменения не сбрасывают актуальный кэш.

Запись каждого JSON-файла выполняется через временный файл и атомарную замену.
Если сохранение метаданных при удалении таблицы не удалось, её файл не удаляется.
Если удаление файла не удалось, выполняется восстановление прежней схемы.
Повреждённый JSON сообщается как ошибка и не заменяется пустыми данными.
Общей транзакции между несколькими файлами нет. База предназначена для одного
процесса; менять её файлы вручную во время работы с кэшем не предполагается.
Пути отсчитываются от текущей директории запуска.

## Структура и зависимости

```text
src/primitive_db/
├── __init__.py   # пустой маркер пакета
├── main.py       # точка входа
├── engine.py     # цикл, вывод и координация операций
├── core.py       # схемы, типы и CRUD
├── utils.py      # файловая система и JSON
├── parser.py     # собственный строгий парсер
├── decorators.py # декораторы и замыкание
└── constants.py  # пути, типы, имена команд и общая конфигурация
tests/           # проверки в отдельных временных базах
demo/            # поэтапные записи asciinema
docs/            # ход разработки и сверка требований
```

В приложении используются только разрешённые модули стандартной библиотеки
`json`, `os`, `time` (разрешённый `shlex` нужен в проверках) и внешние
`prompt`, `prettytable`. SQL-парсеры, ANSI-подсветка и дополнительные
пользовательские команды не добавлены. Ruff — dev-зависимость.

## Проверки, сборка и установка wheel

```bash
make lint
make test
make build
make publish-dry-run
```

`make check` выполняет все эти проверки. Три проверочных файла содержат
10 групп сценариев: таблицы, CRUD, парсер, файловые ошибки, подтверждения и кэш.
Проверки создают собственные временные базы и не используют рабочие записи.
GitHub Actions запускает их для ветки ver2 на Python 3.12 под Linux,
а также проверяет установку wheel вне исходников. Локально проверяется macOS.
Это проверки проекта, не закрытые тесты Практикума.

`make build` выполняет `uv build --clear`: в dist остаётся только текущая сборка.
`make publish-dry-run` выполняет `uv publish --dry-run --trusted-publishing never`.
Настоящая публикация на PyPI не выполняется; токены и пароли не передаются.
В интерактивном терминале uv может запросить авторизацию даже для dry-run.
Проверка запускается без управляющего терминала и с закрытым стандартным вводом.
Фиктивные учётные данные не используются.

```bash
uv tool install --force dist/*.whl
database
```

Если uv сообщает, что каталог инструментов отсутствует в PATH, выполните
`uv tool update-shell` и откройте новый терминал. Для изоляции рабочей базы
запускайте database из одной выбранной директории.
