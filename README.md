# Примитивная база данных

Арсений Веткасов, группа M-26-555.

Консольная база данных на Python: создание таблиц, добавление, просмотр,
изменение и удаление записей. Данные сохраняются в JSON между запусками.

## Установка с нуля

Нужны Git и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Проект использует Python 3.12 или новее; uv подготовит нужный интерпретатор
и виртуальное окружение.

Скопируйте этот блок в терминал:

```bash
git clone https://github.com/vetkasov/python2-vetkasov-M-26-555.git
cd python2-vetkasov-M-26-555
uv sync --locked
uv run database
```

Если проект уже скачан, перейдите в его папку и выполните только две
последние команды. `uv run project`, `uv run python -m primitive_db.main`
и `make run` запускают то же приложение.

Для существующей локальной папки автора:

```bash
cd ~/Desktop/university/python_programming_2
uv sync --locked
uv run database
```

## Первый сеанс

Следующие команды вводятся **внутри приложения**, после приглашения
`Введите команду:`, а не в командной оболочке:

```text
create_table users name:str age:int is_active:bool
insert into users values ("Sergei", 28, true)
select from users
update users set age = 29 where name = "Sergei"
select from users where ID = 1
info users
delete from users where ID = 1
y
drop_table users
y
exit
```

Строка `y` отвечает на запрос подтверждения удаления. Любой другой ответ
отменяет действие. `help` показывает справку; `exit`, Ctrl+C или конец ввода
завершают работу.

## Команды и правила ввода

| Команда | Назначение |
| --- | --- |
| `create_table <таблица> <столбец:тип> ...` | Создать таблицу |
| `list_tables` | Показать таблицы |
| `drop_table <таблица>` | Удалить таблицу после подтверждения |
| `insert into <таблица> values (...)` | Добавить одну запись без ID |
| `select from <таблица>` | Показать все записи |
| `select from <таблица> where <столбец> = <значение>` | Отфильтровать записи |
| `update <таблица> set <столбец> = <значение> where <столбец> = <значение>` | Обновить записи по условию |
| `delete from <таблица> where <столбец> = <значение>` | Удалить записи по условию |
| `info <таблица>` | Показать схему и количество записей |
| `help`, `exit` | Справка и выход |

- Типы столбцов — только `int`, `str`, `bool`, строчными буквами.
- Имена состоят из латинских букв, цифр и `_`; регистр учитывается.
- `ID:int` всегда первый и генерируется автоматически. Изменять ID запрещено.
- Значения передаются в порядке схемы, без ID; все пользовательские поля обязательны.
- Строки — в одинарных или двойных кавычках. Числа и bool — без кавычек.
- Булевы значения принимаются в любом регистре: `true`, `True`, `TRUE`.
- Ключевые слова команд пишутся строчными. `"28"` не подходит для `int`.
- Пробелы между элементами допустимы; пробелы и запятые внутри строк сохраняются.
- `where` содержит одно равенство; `update` изменяет один столбец.
- Один `insert` — одна таблица и одна группа значений. Лишние токены запрещены.

Например, `insert into users values ("Ivanov, Ivan",22,FALSE)` — корректная
команда. Результаты выборок выводятся через PrettyTable с первым столбцом ID.
ID вычисляется как максимальный существующий ID плюс один; после удаления
последней записи её ID может использоваться повторно.

## Хранение данных

Схемы находятся в `db_meta.json`, записи — в `data/<имя>.json`.
Эти файлы создаются при работе и исключены из Git. Отсутствующий файл записей
означает пустую таблицу; `drop_table` физически удаляет его.
Для различия имён `users` и `Users` на macOS заглавные буквы в имени файла
кодируются: `users.json` и `%55sers.json`.

Пути отсчитываются от текущей директории. Запускайте программу из одной
выбранной папки, чтобы продолжать работу с той же базой.
JSON записывается через временный файл и атомарную замену. Повреждённый файл
не заменяется пустой базой. При ошибке сохранения схемы файл таблицы не удаляется;
при ошибке удаления файла выполняется восстановление схемы. Общей транзакции
между файлами нет. Приложение рассчитано на один процесс.

## Декораторы и кэш

`handle_db_errors` обрабатывает ошибки операций. `confirm_action` подтверждает
удаление таблиц и записей. `log_time` измеряет `insert` и `select` через
`time.monotonic()` и выводит длительность с тремя знаками после точки.

`create_cacher()` хранит кэш в замыкании. Ключ строится в engine.py из имени
таблицы и условия `where`, включая отсутствие условия. Повторная выборка
использует кэш; после сохранённых `insert`, `update`, `delete`, `drop_table`
он пересоздаётся. Отмена и ошибка сохранения не сбрасывают актуальный кэш.
Менять файлы вручную во время работы с кэшем не предполагается.

## Проверка и сборка

В терминале, из корня проекта:

```bash
make lint
make test
make build
make publish-dry-run
```

`make check` выполняет все четыре проверки. Тесты находятся в `.github/checks`
и используют собственные временные базы. CI проверяет Python 3.12 под Linux;
локально приложение проверено на macOS. Закрытые тесты Практикума не предоставлены.

Сборка создаёт wheel и архив в `dist/`, предварительно удаляя устаревшие сборки.
Пробная публикация выполняет `uv publish --dry-run` без загрузки на PyPI.
Автопоиск OIDC отключён; закрытый ввод и перенаправленный вывод исключают
интерактивный запрос авторизации, а `pipefail` сохраняет код ошибки uv.
Токены и пароли не подставляются.

Установить собранный пакет как отдельную команду:

```bash
uv tool install --force dist/*.whl
database
```

Если каталог инструментов не входит в PATH, выполните `uv tool update-shell`
и откройте новый терминал. Имя дистрибутива — `project-2-vetkasov-m-26-555`,
импортируемого пакета — `primitive_db`. Прямые зависимости приложения:
`prompt`, `prettytable`; Ruff — зависимость разработки.
